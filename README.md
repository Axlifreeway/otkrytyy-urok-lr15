# ОПЦ.07 «Аэропорт» — лабораторные по SQL

Лабораторные работы по базам данных, где каждая команда SQL сразу видна на схеме самолёта.
PostgreSQL работает прямо в браузере (PGlite), данные и задания у каждого студента свои — по номеру варианта.

| Папка | Что это |
|---|---|
| `index.html` | главная — карта «Город SQL»: аэропорт (ЛР-13–16), пиццерия (ЛР-17–20), стройка. Пока лабы пиццерии закрыты, сразу ведёт в аэропорт; посмотреть карту — `/?map` |
| `airport/`, `pizza/` | главные «миров»: табло вылетов и посадочные талоны; экран заказов и чеки. Вход по PIN и прогресс — общие (`common/home.js`) |
| `lr13-3d/`, `lr14-3d/` | 3D-лабы ЛР-13 (INSERT) и ЛР-14 (UPDATE, DELETE): робот-СУБД обходит строки, 12 уровней, протокол с отправкой преподавателю, бесконечная тренировка после уровней (`src/practice.js`) |
| `lr15-3d/`, `lr16-3d/` | 3D-лабы ЛР-15 (SELECT: столбцы, отбор, порядок, NULL) и ЛР-16 (JOIN: связи, две и три таблицы, LEFT JOIN). Открыты всем, как ЛР-13/14; общий ход — `common/qlab.js`, бесконечная тренировка после уровней — вопросы из базы студента (`src/practice.js`) |
| `lr17-3d/` … `lr20-3d/` | 3D-лабы пиццерии «SQL Pizza» на одной базе (`common/pizzadata.js`, сцена — `common/three/pizzeria.js`): ЛР-17 (GROUP BY и HAVING — коробки заказов раскладываются стопками по группам), ЛР-18 (подзапросы, NOT EXISTS и ловушка NOT IN), ЛР-19 (закрепление: 15 запросов), ЛР-20 (транзакции: BEGIN, COMMIT, ROLLBACK, ошибка внутри транзакции, приглашение psql). **Закрыты, пока их не откроет преподаватель** (панель → «Группы и списки» → «Доступ к лабораторным»); карта города появляется, когда открыта хотя бы одна |
| `testing/` | проба: ЛР-17 в пиццерии из готовых моделей KayKit и Kenney (CC0) — посмотреть, как это выглядит; см. `testing/README.md` |
| `labs/` | 2D-тетради ЛР-13, 14, 16 (брифинг, предсказания, смена, контрольный рейс); см. `labs/ПРЕПОДАВАТЕЛЮ.md` |
| `mvp/` | MVP открытого урока ЛР-15 «Посадка по запросу» |
| `teacher/` | панель преподавателя: кто где застрял (за любой день), журнал команд, отчёты студентов, группы и PIN |
| `server/` | `labsrv.py` — вход по PIN, прогресс, события для панели (Python + SQLite); как выложить — `server/README.md` |
| `common/` | общий код: 3D-движок (`three/`), каркас лабы (`shell.js`), вход и синхронизация, проверка результата, стили |
| `vendor/pglite/` | PostgreSQL для браузера (PGlite 0.5.8) |
| `tests/`, `tools/` | тесты и сборка |
| `_архив/` | отклонённые и старые варианты |

## Сборка и проверка

    npm install
    npm run build    # собрать game.js всех 3D-лаб (lr13-3d … lr20-3d) из src/ и common/
    npm run check    # game.js в репозитории собран из текущих исходников?
    npm test         # данные вариантов не изменились, разбор команд, сервер
    npm run e2e      # все уровни 3D-лаб и тетрадей в браузере, телефон, вход по PIN → панель
    npm run format   # отформатировать JS и CSS (Prettier); npm run lint — проверить

`game.js` хранится в репозитории: лабу можно открыть двойным щелчком без сборки. После правки
`src/` или `common/` не забудьте `npm run build`.

`tests/variants.test.mjs` сверяет данные и задания всех вариантов 0–60 со снимком: если они
поменялись, у студентов «поедет» рассадка и сохранённый прогресс. Обновлять снимок
(`UPDATE_SNAPSHOT=1 npm test`) — только когда данные меняются намеренно.

Для сравнения картинки до и после правок: `SHOTS=папка npm run e2e` снимает сцену в начале
каждого уровня, `node tests/shotdiff.mjs папка-до папка-после` показывает долю отличающихся пикселей.
