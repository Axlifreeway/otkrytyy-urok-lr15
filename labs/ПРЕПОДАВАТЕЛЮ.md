# Аэропорт — рабочие тетради ЛР-13, 14, 16

Каждая тетрадь — полная лабораторная на 90 минут. PostgreSQL работает в браузере
(PGlite из `../vendor/pglite`, при неудаче — с CDN). Сервер не нужен.

## Как открыть

* Двойной щелчок по `index.html` или по файлу лабораторной (Chrome / Edge / Яндекс).
  Если открыть просто как файл, PGlite берётся с CDN, поэтому нужен интернет.
* Для класса удобнее выложить папку `otkrytyy-urok-lr15` целиком (вместе с `vendor/`)
  на GitHub Pages или на учебный сервер. Тогда всё грузится с одного адреса.
* Номер в журнале задаётся при первом входе и общий для всех тетрадей.
  Номер 0 — демонстрационная смена для проектора.
* Кнопка «проектор» в шапке включает крупный шрифт.

## Файлы

| Файл | Что в нём |
|---|---|
| `core.js`, `core.css` | движок: выполнение SQL по командам, разбор ошибок по-русски, снимки и сравнение состояния, вкладки, уровни, предсказания, контрольный рейс, протокол |
| `world.js` | общий мир: авиакомпании, направления, схема салона, анимация пассажиров |
| `lr13.html`, `lr14.html`, `lr16.html` | данные по номеру, схема базы, уровни, сцена |

Новая лабораторная — это ещё один `lrNN.html` с объектом `LAB`.
Проще всего начинать с копии `lr14.html` (если сцена строится по разнице
состояний) или `lr16.html` (если по ответу запроса).

## 90 минут

| Мин. | Вкладка | Что делает группа |
|---|---|---|
| 0–10 | Брифинг | Преподаватель на проекторе (номер 0) нажимает кнопки «Попробуйте» по порядку |
| 10–20 | Предскажи | 5–6 карточек: сначала ответ, потом запуск. Ответ фиксируется, второй попытки нет |
| 20–65 | Смена | 8–10 уровней и бонусы ★. Цель видна на схеме. После двух промахов появляется подсказка |
| 65–80 | Контрольный рейс | Новая задача без подсказок и без подсветки отличий, две попытки сдачи |
| 80–90 | Протокол | ФИО, ответы на вопросы, печать или PDF; защита у стола |

## Защита: изменить решение при преподавателе

Откройте у студента любой пройденный уровень и попросите изменить решение.
На это даётся минута.

**ЛР-13**
* «Добавь пассажиру № 1 второй чемодан, а в той же команде — ещё один чемодан другому пассажиру».
* «Внеси рейс, у которого ещё нет выхода, — двумя способами».
* «Внеси новую авиакомпанию и её рейс одним запуском, но рейс поставь первым — что ответит база и почему?»

**ЛР-14**
* «Верни пассажира из уровня 1 на прежнее место».
* «Удали рейс из уровня 8 — что нужно сделать сначала?»
* «Что будет с багажом, если правило внешнего ключа заменить на RESTRICT?»
* «Покажи, как теперь выбрать только действующих пассажиров» (уровень 9).

**ЛР-16**
* «Добавь в ответ уровня 3 название рейса — сколько таблиц теперь?»
* «Перенеси условие на вес в бонусе из ON в WHERE — кто пропал и почему?»
* «Замени LEFT JOIN в уровне 8 на JOIN — сколько строк?»
* «Назови, из каких строк собрана любая строка ответа уровня 7».

## Чем защищено от списывания

* Данные, номера рейсов, места, бирки, пороги и города — свои у каждого номера.
  Чужой запрос на вашей базе даёт другую картинку.
* В ЛР-14 пульт не выполнит UPDATE/DELETE с условием без предшествующего SELECT
  с тем же условием, а числа строк из обоих попадают в протокол.
* В протокол пишутся все предсказания, решение каждого уровня, промахи, подсказки,
  число запусков и вставки из буфера обмена.

## Ограничения этой версии

* Эталоны лежат в коде страницы. Для открытого урока это не важно; для зачётной
  проверки нужен сервер, который сверяет ответ с эталоном на данных студента.
* Прогресс хранится в браузере конкретного компьютера (localStorage) и
  преподавателю не виден. Протокол студент отправляет кнопкой «📤 Отправить преподавателю»
  (отчёт появится в панели, «📄 Отчёты»); сервер узнаёт студента по входу с PIN в 3D-лабу
  в этом же браузере. Без сервера — печать или PDF, как раньше.
* Сообщения СУБД — английские, как в настоящем PostgreSQL; под каждым есть
  пояснение по-русски.
