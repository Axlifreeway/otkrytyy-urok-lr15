# Открытый урок «Посадка по запросу»

**ОПЦ.07 Основы проектирования баз данных · ИИ б.9 · по ЛР-15 «Выборка
данных: SELECT, WHERE, ORDER BY» · 90 минут, компьютерный класс**

Черновик, 07.10.2026. Прежний вариант («Живая таблица») отклонён — в
компьютерном классе нельзя вставать и строиться; лежит в `_архив`.

---

## 1. Идея

Ответ на запрос — не сухая таблица, а **картинка, понятная любому
пассажиру**. Слева на экране — поле для запроса, справа — схема салона
самолёта сверху. Каждое кресло — строка таблицы `passenger`.

* `WHERE` → загораются кресла тех, кто подходит;
* `ORDER BY` → идёт **посадка**: пассажиры проходят по проходу и
  садятся в том порядке, который задал запрос;
* `LIMIT 12` → после двенадцатого двери закрываются;
* ошибся в условии → загорелась половина салона, видно с задней парты.

Таблица результата тоже есть — свёрнутой полоской под схемой: картинка
главная, таблица — подтверждение.

## 2. Чем это отличается от «Электронной тетради»

| «Электронная тетрадь» | «Посадка по запросу» |
|---|---|
| набрал команду — получил таблицу | набрал команду — **самолёт сделал то, что ты сказал** |
| результат понимает тот, кто знает SQL | результат понимает **любой гость**: «загорелись места у окна» |
| задание — текст | задание — **картинка**: «напиши запрос, чтобы загорелось вот так» |
| итог урока — заполненная тетрадь | итог урока — самолёт каждого студента «улетел» на табло вылетов |

Для комиссии это видно без объяснений: человек, не знающий SQL, всё
равно понимает, что происходит на экране.

## 3. Как устроена картинка (правила, которые и учат SQL)

Правила простые, но каждое само по себе — содержание ЛР-15:

| Правило схемы | Чему учит |
|---|---|
| Подсвечиваются кресла из столбца `seat` ответа. Нет `seat` в `SELECT` — схема пишет: «В ответе нет мест — не знаю, кого подсветить» | `SELECT` выбирает **столбцы**; что не попросил — того нет |
| Порядок посадки = порядок строк ответа | `ORDER BY` задаёт порядок |
| Без `ORDER BY` пассажиры идут вразнобой, и при каждом запуске — по-разному (сервер перемешивает) | порядок без `ORDER BY` не гарантирован |
| `LIMIT` — двери закрываются после N-го | `LIMIT` отрезает первые N **после** сортировки |
| `DISTINCT city` без мест → схема гаснет, справа — табло городов | `DISTINCT` убирает повторы, а не «выбирает пассажиров» |
| Пустой ответ — салон тёмный, сверху: «0 строк» | `= NULL` не находит ничего |

## 4. Данные

Одна таблица — соединений нет (они на ЛР-16), агрегатов нет (ЛР-17):

```
passenger (
    id          integer PRIMARY KEY,
    seat        varchar(3),      -- '12C'
    row_no      integer,         -- 12
    letter      char(1),         -- 'C'
    full_name   varchar(80),
    fare_class  varchar(10),     -- бизнес / комфорт / эконом
    birth_year  integer,
    city        varchar(40),
    baggage_kg  integer,
    with_child  boolean,
    loyalty     varchar(10)      -- серебро / золото / NULL
)
```

Салон: ряды 1–4 бизнес (A, C, D, F), 5–8 комфорт, 9–30 эконом (A–F),
около 170 мест. **У каждого студента своя рассадка** — данные
генерируются по номеру в журнале: соседский запрос даёт соседскую
картинку, а не твою.

## 5. Ход урока (90 минут, все на местах)

| Мин. | Этап | Что происходит |
|---|---|---|
| 0–5 | Вход в тему | На проекторе — анимация хаотичной посадки: люди толпятся в проходе. «Авиакомпания каждый день решает, кого сажать первым. Как она это говорит компьютеру?» Тема без объявления. |
| 5–15 | Демонстрация | Преподаватель на проекторе: `SELECT seat FROM passenger WHERE fare_class = 'бизнес'` — загорается нос самолёта. Потом убирает `seat` из `SELECT` — схема гаснет с сообщением. Потом `ORDER BY row_no DESC` — посадка с хвоста. Правила схемы — на одном слайде. |
| 15–27 | «Предскажи салон» | На проекторе запрос; каждый **сначала щёлкает кресла на своей схеме**, которые, по его мнению, загорятся, и только потом запускает. На проекторе — **тепловая карта предсказаний группы** рядом с настоящим результатом. Два запроса здесь — ловушки: скобки (`AND … OR …`) и `loyalty = NULL`. Разница между «что думала группа» и «что сделала СУБД» — видна всем. |
| 27–70 | Обратная задача | Студент видит **целевую картинку** — подсвеченные места или заданный порядок посадки — и пишет запрос, который даст ровно её. 10 уровней (раздел 6). Совпало — самолёт выруливает и взлетает, на проекторе на **табло вылетов** его рейс меняет статус на «Вылетел». Уровни усложняются; быстрые идут к бонусным. |
| 70–82 | Заказчик | Гость из комиссии играет начальника смены аэропорта и **говорит вслух**: «Посадите сначала пассажиров с детьми, потом бизнес, остальные — с хвоста». Группа пишет запрос; лучшие варианты преподаватель запускает на проекторе — гость видит, как выполняется его просьба. |
| 82–90 | Итог | Табло вылетов: сколько рейсов улетело. Одна фраза от желающих: «что SQL делает с самолётом». ДЗ — ЛР-15 на своей базе, с вопросом: «как бы выглядела картинка вашей области?» (кинотеатр — зал, гостиница — этажи, поликлиника — кабинеты). |

## 6. Уровни обратной задачи

Целевая картинка у каждого студента своя (своя рассадка). Подпись под
картинкой — одна строка простым языком, без слов SQL.

| № | Картинка и подпись | Что нужно в запросе |
|---|---|---|
| 1 | Горит весь бизнес-класс. «Кого зовут первыми?» | `WHERE` с равенством |
| 2 | Горят все места у окна. «Кто увидит взлёт?» | `IN ('A', 'F')` |
| 3 | Горят ряды с 10 по 15. «Первая группа эконома» | `BETWEEN` |
| 4 | Горят несколько разрозненных мест. «Что у них общего?» — подписи нет, надо **самому изучить данные** этих людей | найти закономерность (например, фамилия на «К» → `LIKE`) |
| 5 | Горят трое. «У них нет карты лояльности» | `IS NULL`; `= NULL` даст тёмный салон |
| 6 | Горят пассажиры с детьми **и** пожилые — но только в экономе | скобки: `(a OR b) AND c` |
| 7 | Анимация: посадка с хвоста | `ORDER BY row_no DESC` |
| 8 | Анимация: с хвоста, а внутри ряда — от окна к проходу | сортировка по двум столбцам |
| 9 | Анимация: первые 12 с хвоста, потом двери закрываются | `ORDER BY … LIMIT 12` |
| 10 | Финальный рейс: правило из трёх условий + порядок, подпись — фраза диспетчера | всё вместе |
| ★ | Бонусы для быстрых: «самый тяжёлый багаж садится последним», «по одному пассажиру из каждого города» и т. п. | `DESC`, `DISTINCT` |

Уровень засчитывается, когда **набор мест** (а на уровнях 7–9 — ещё и
**порядок**) совпадает с целью. Если не совпало, схема показывает разницу:
лишние места — красным, недостающие — пунктиром. Это и есть подсказка —
без слов «неверно».

Уровень 4 — главный против бездумного копирования: правила в задании
нет, его надо **вывести из данных**, а данные видит только студент.

## 7. Что видно на проекторе

Переключается преподавателем:

* **его салон** — для демонстрации;
* **тепловая карта предсказаний** — во время «Предскажи салон»;
* **табло вылетов** — во время уровней: строка на студента (рейс
  `ИИ-25-07`), статус «Регистрация → Посадка → Вылетел», текущий
  уровень. Без процентов и мест в рейтинге — только «улетел / в пути»;
* **салон любого студента** — щелчком по его рейсу (если хочет показать
  удачное решение).

## 8. Что видит комиссия

* Абстрактное понятие получает **понятный образ**: условие отбора =
  какие кресла загорелись, сортировка = порядок посадки. Человек без
  подготовки следит за уроком наравне со студентами.
* **Предсказание до выполнения** (тепловая карта группы) — ошибки в
  понимании видны до того, как они попали в работу.
* **Обратная задача** — от результата к запросу: уровень анализа, а не
  воспроизведения.
* Гость — не наблюдатель, а **заказчик**, чья просьба выполняется у него
  на глазах.
* Все 90 минут работают все: в начале — предсказание, потом —
  собственные уровни.
